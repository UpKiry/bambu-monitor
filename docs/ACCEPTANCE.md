# 方案 A：验收规格与追踪矩阵

## 当前状态与判定原则

**本文是未来实施的验收规格，所有新增用例当前均为待执行。** 已选方案 A，当前轮只写文档，没有实现或运行云认证、采集器、宿主集成或本规格测试。旧组件的离线检查结果不能自动覆盖这些新增需求。

需求编号以 [需求规格](REQUIREMENTS.md)为准；阶段编号与 [实施计划](IMPLEMENTATION-PLAN.md)一致：M0 宿主核实、M1 离线核心、M2 认证/设备发现、M3 云 MQTT/可靠性、M4 宿主集成、M5 数据状态 UI、M6 端到端。

结果只能记录为 `passed / failed / pending / not-applicable`，并附证据。缺少账号或设备时使用 pending 并写清所缺条件；不能把真实云/HIL改成不适用，也不能因其 pending 停止可执行的 M1 工作。每项验收记录至少包含：需求/用例编号、代码版本、协议 profile、平台与依赖、输入类别、步骤、预期、实际、证据和未覆盖项。不得记录秘密、会话凭据或全量账户响应。

## AC-08：新鲜度、增量与身份的必测序列

以下 T0、T+N 是可控单调时钟的相对时点，配套墙钟使用带时区RFC3339。`updated_at`指实际观察时间；它与field有效性依据不是同一个字段。先使用需求规定的已验证delta profile；未知profile另测。60秒为连接证据设计阈值，不是通用字段TTL。

| 子用例 | 输入序列 | 必须断言的结果 |
| --- | --- | --- |
| AC-08a 首次无基线 | 新身份/新generation，尚无目标遥测；随后仅收到broker ping、其他设备消息和无效JSON | 未观察字段unknown，已确认不支持字段unsupported。last_message_at及目标liveness不因这些消息续期，不宣称基线完整。 |
| AC-08b 仅变化字段持续上报 | T0有效基线含总层数300、槽余量75、喷嘴220；以后每10秒只上报有效进度delta，持续至少180秒 | 当前generation/任务/槽身份有效、profile已确认遗漏语义时，未变化字段继续valid；它们的值和updated_at保持T0，不在T+60统一stale。generated_at可推进，PC basis显示delta/task/tray retained。 |
| AC-08c 数值相同但明确重观测 | 在AC-08b中T+70明确上报喷嘴220，其他字段仍缺席 | 喷嘴updated_at推进至本次观察；总层数和槽余量的updated_at不变。判断使用“字段是否明确出现”，不使用“数值是否变化”。 |
| AC-08d 只有broker ping | 目标遥测停止，网络仍有MQTT ping/pong；超过liveness阈值 | 已有值stale、原updated_at保留；unknown/unsupported不变；状态原因是目标遥测无证据，不能说打印机断电。Pong不续目标证据。 |
| AC-08e generation恢复 | 断线→新generation；先收到一个部分delta，再收到profile确认的完整基线 | 旧代迟到消息忽略。第一个delta不能使未重观测的旧字段或完整基线恢复；只允许有本代明确证据的字段恢复。完整基线后才建立相应本代遗漏语义，字段时间仅按实际观察更新。 |
| AC-08f 任务切换 | 同一网络generation内任务A变为任务B；B尚未上报总层数/进度，温度仍有目标遥测 | A的任务作用域值不继续作为B的valid值；B未知字段为unknown。温度若依据仍有效可保留；不能将整个缓存统一清零或统一续命。 |
| AC-08g 稳定AMS与换料 | 稳定AMS/槽/耗材仅其他delta超过180秒；之后同槽换料或明确空槽 | 稳定期余量可valid而updated_at不变。身份改变撤销旧耗材余量，新余量未上报为unknown；明确空槽不显示旧75%，也不把缺失余量当有效0%。 |
| AC-08h 缺席不等于删除 | 基线含多个AMS/槽；增量只含其中一个单元或一个槽，并有乱序 | 其他单元/槽不被当作移除；按ID合并。完整列表的删除语义必须有profile证据，不能凭不完整数组推断。 |
| AC-08i 未知profile | 型号/固件超出验证profile，报文位置或遗漏语义无法确认 | 不启用通用delta-retained续期；未观察unknown，有旧值但有效性失去依据为stale；诊断明确profile限制，不编造所有13项支持。 |
| AC-08j 局部无效与真实0 | 某字段从有效值变为负余量/非法字符串；另一字段明确上报0；其他目标delta有效 | 无效字段有旧值则stale、无旧值则unknown；真实0保持valid；无关字段按自身依据保持，局部错误不成为全设备错误。 |
| AC-08k 墙钟跳变 | 目标delta持续，墙钟前跳/后跳，单调时钟正常；随后停止目标消息 | liveness按单调时钟，不因墙钟跳变提前超时或永久有效；输出不制造未来updated_at，异常时间来源可诊断。 |
| AC-08l 身份与迟到结果 | 同名设备切换、账号/区域切换，旧HTTP/MQTT响应晚到；旧任务或旧槽消息到达 | 旧identity/generation/epoch不能改变新实例值、时间或质量。无明确新目标观测时为unknown/旧缓存stale，不能通过其他机器心跳恢复。 |

profile识别、基线判据、目标活跃事件列表、任务/槽身份规则应有可审阅fixture。若目标固件不提供可靠基线或身份信息，必须缩小支持声明并说明限制，不能靠定时pushall或随意更新timestamp掩盖不确定性。

## M0 宿主专项门禁

M0 报告至少回答：真实客户端和固件版本/能力是什么；源码入口在哪里；快照由谁接收、怎样绑定当前组件实例；13个值加质量状态是否在变量/字节预算内；退出/断连后旧快照能否被拒绝；改动只在本仓库还是涉及外部产品。

M0 不能只交“离线JSON通过”。最小步骤为：

1. D层追踪真实通道与接收边界，列明composition/bridge/fetch各自限制。
2. F层用标记清楚的测试快照检查一个标量、实例切换、过期及拒绝路径。
3. 有设备时H层确认协商和实际显示，再扩大至13项和质量状态。
4. 需要外部源码改动时先取得明确范围授权；缺少源码或设备则记录pending，不修改安装应用/技能/用户profile，不静默删指标。

M0未有H证据不阻止M1–M3的纯采集器工作，但M4的真实目标选择和完整上屏承诺必须依据M0结果。

## 真实云与端到端记录

首轮 R 层只要求一个明确区域、一个用户本地授权账号、一个目标机型/固件。记录所用登录分支、设备ID脱敏引用、profile、实际可用字段与缺失项；cn/global均需离线映射测试，未测区域的真实认证保持pending。

M3连续观察建议至少30分钟，包含正常接收、一次受控网络中断/恢复，以及可自然出现的任务变化。若没有自然任务变化，相关场景依赖U/F证据并将真实覆盖列为pending，不能控制打印机制造事件。M6应核对三页、全部按键、质量状态、账号失效、目标离线、USB重连和退出清理；不是所有故障都必须在真实账号上反复制造，依据层次和可控风险选择方法并清楚记录。

## 完成等级

- **文档已准备**：需求、计划和本规格可审阅；当前所属等级，不表示新增功能通过。
- **离线核心通过**：M1及M2/M3相应fake用例通过，缺少外部条件的真实层仍pending。
- **云采集器阶段通过**：指定账号/区域/机型的M2–M3通过，能输出真实快照；不宣称设备显示完成。
- **完整MVP通过**：M0–M6适用项均有证据，包含目标宿主和设备HIL；限制与未测平台已列明。后续打包、导入、同步和发布仍分别记录，不由验收文档自动执行。
