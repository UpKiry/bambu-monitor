## 阶段顺序

| 阶段 | 核心工作 | 退出条件 |
|---|---|---|
| M0 宿主核实 | 生产源码/实际协商、13项与质量状态预算、单标量和断连路径 | 有可追踪接入决策；缺少设备/外部源码明确pending |
| M1 离线核心 | 配置与消息边界、解析、增量缓存、有效性、快照、回放 | 不依赖账号的真实核心与测试可运行 |
| M2 认证/设备发现 | cn/global、密码/验证码/MFA、密钥库、显式选设备 | 认证状态机与离线覆盖，首个实际账号分支单独记录 |
| M3 云订阅可靠性 | TLS、SUBACK、首帧、初始化限频、重连代次与退出 | 规范化云快照、断网/失效语义和观察记录 |
| M4 宿主集成 | 原生provider或受控入口、完整投影、USB仲裁 | 按M0已核实并获授权的范围实际接通 |
| M5 状态UI | 动态机型/任务、未知/不支持/过期、AMS映射 | 预览先确认，再实现与核对预算 |
| M6 端到端 | 真实云、自然任务变化、断网恢复、三页实机 | 逐项填写验收矩阵，分别报告采集/USB/实机 |

M0优先，M1可以并行；缺设备不阻止离线开发。M4依赖M0决策，M6依赖真实云与显示两条链路。宿主限制未核实时不能承诺完整上屏或无需固件更新，也不能自动删减指标。

## 宿主与数据的重点

composition总vars和service bridge绑定目前≤8；PC fetch是每来源8项，拆来源的声明可通过但网络不支持私有鉴权/本机HTTP，不能自动解决实时消费。`app/snapshot`有入口参考，当前13变量和额外质量状态仍需核对生产代码与目标设备；详见 [M0](IMPLEMENTATION-PLAN.md)。

增量未出现字段保留旧值和旧观测时间。稳定字段不能只因60秒未变化一律stale；有效性要结合可靠的目标设备活跃证据、会话generation、初始基线、任务/耗材作用域。broker ping、重新生成快照不能伪造新观测。

## 后续范围

首版只做单账户、显式选择的一台设备、选定喷嘴和AMS的监控。若目标机型没有腔温/辅助风扇/余量等能力，按unknown/unsupported显示，不伪造13项全部可用。

本地MQTT是独立后续提供器，复用模型和显示投影，不自动回退。NAS/容器、跨机私有接口、多账户、多机同时显示和完整多喷嘴UI另行计划。

发布与同步在完成所需验收后单独进行；保持组件ID不变，不自动操作真实打印任务。需求变化、外部产品源码修改及UI调整遵循交接中的范围约束。
