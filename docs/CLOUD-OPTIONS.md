# 云端接入方案比较

当前决策：**2026-11-18 用户已选择 A：自研 Bambu Cloud 适配器。实时数据提供器尚未实现。** 本文保留为历史选型依据，B/C不在当前实施范围。后续以 [需求](REQUIREMENTS.md)、[实施计划](IMPLEMENTATION-PLAN.md)和 [验收](ACCEPTANCE.md)为准。比较资料不代表云登录、云 MQTT、USB或实机已验证，也不要求在文档中填写凭据。

本阶段排除打印机的本地 MQTT；**云 MQTT 可以使用**。三条路线均可满足。云 HTTP 负责认证、设备发现和任务元数据；云 MQTT 负责进度、温度、层数、风扇和 AMS 遥测。设备列表或任务历史 HTTP 不能承诺补齐屏幕 13 项读数。接口证据见 [云协议研究](CLOUD-PROTOCOL.md)。这些是社区研究的私有协议，不能称为官方稳定开放 API。

## 共同的数据边界

```text
A：自研 HTTP + 云 MQTT ─────────┐
B：封装 pybambu 的云端实现 ────┼→ 规范化快照 → 宿主适配 → 显示变量
C：HA 接入 Bambu Cloud → HA API ┘
```

规范化结构以 [内部快照契约](../schemas/printer-snapshot.schema.json)为准。它是项目自定的待实现提供器契约，不是拓竹报文或固件/USB 协议。三条路线共享它，未来 LAN 提供器也输出相同结构。

- 有效数值 `0` 与 `unknown`、`unsupported` 必须区别；后两者的值及更新时间为 `null`。
- `stale` 保留最后一个数值及它的实际更新时间；不能用快照生成时间假装读数更新。
- HTTP 摘要在线、MQTT broker 连接成功、打印机实际在线及完整状态就绪是不同事实。
- 凭据失效进入契约已有的 `auth_required`，不伪装成打印机离线。
- AMS 按单元 ID 和槽 ID 合并。当前契约每个单元最多四槽，组件显示四槽；支持更多槽的机型须先演进契约/UI，不能静默截断后声称完整支持。

[配置样例](../examples/provider.example.toml)是设计文件，当前没有配置加载器或可运行提供器。区域、密钥库引用、超时与重连参数均待实现；60秒是目标设备活跃证据超时的设计初值，不是所有字段TTL或云端保证的推送周期。

## A：自研最小云适配器

独立 PC 提供器负责区域化登录、验证码/MFA、设备选择、UID 获取、TLS 云 MQTT、增量缓存及快照输出。用户明确选择打印机，不默认选第一台。第一版只做监控，不接打印控制、相机、FTP、模型下载或 MakerWorld。

**优点：** 依赖少、职责清楚，适合长期独立分发；HTTP 请求量、日志和对外数据可精确控制。

**代价：** 本项目维护认证变化、验证码交互、机型字段与重连。最小订阅演示不等于可持续运行的提供器。token 刷新不可作为可靠前提，必须提供失效后重新认证流程。

**基础设施与凭据：** 一台持续运行采集进程的电脑；打印机绑定云账号并能联网。电脑与打印机无需在同一 LAN。用户在 PC 本地登录，token 存系统密钥库，不进入组件、设备、快照或日志。选择方案后再实现登录入口及私有存储。

## B：固定 pybambu 版本再封装

复用 [ha-bambulab 固定提交](https://github.com/greghesp/ha-bambulab/tree/e3c73139d443e9183ed2f804be30d2f2e53bbe66)内部 `pybambu` 的云认证与 MQTT 客户端，将模型回调转换为规范化快照。

必须设置 `local_mqtt: false`、`host: ""`，禁用相机并检查不需要的 FTP、模型、封面和缓存功能；不能只设一项开关就声称所有副作用已隔离。

**优点：** 复用已实现的认证、重连和多机型解析，减少协议重复开发。

**代价：** `pybambu` 是 HA 仓库内部模块，不是稳定独立 SDK。需验证独立 Python 环境依赖、初始化副作用、线程回调、资源释放与升级兼容；固定提交，不能浮动跟随 main。参考代码存在输出响应正文的调试/错误日志和额外元数据请求，封装时必须审查并裁剪或脱敏，不能仅关闭相机就认定安全。复用代码时保留 MIT 版权和许可。

**基础设施与凭据：** Python 提供器进程，不要求完整 HA 或本地 broker。登录交互和 PC 私有凭据管理仍需本项目实现。

**未来 LAN：** 上游有 LAN 分支，但本阶段关闭。将来经用户选择作为独立提供器启用，不自动回退。

## C：Home Assistant 云桥接

HA 安装 ha-bambulab 并连接 Bambu Cloud；项目通过 HA API 读取所选实体。配置需关闭 local MQTT，选择 `skip_local_mqtt`，打印机 IP 留空。[固定配置流程](https://github.com/greghesp/ha-bambulab/blob/e3c73139d443e9183ed2f804be30d2f2e53bbe66/custom_components/bambu_lab/config_flow.py)确实提供该选项。

项目可用 HA REST 获取初始状态，再用 WebSocket 订阅变化。项目访问 HA 的 HTTP/WebSocket 不等于连接打印机本地 MQTT，不需要新建本地 broker。实体 ID 与单位必须实际发现和配置，不能硬编码文档示例名。

**优点：** 已有 HA 时开发最少，拓竹认证和协议维护主要由集成承担。项目不持有 Bambu token。

**代价：** 持续运行 HA，维护 HA/集成版本与实体映射；若只为一个屏幕从零部署 HA，运行成本可能高于 A/B。

**凭据：** Bambu 凭据留在 HA；项目持有 HA 访问凭据，也须私有保存。`unknown`/`unavailable` 不转成 0。

**未来 LAN：** HA 内部模式可在用户新选择后改变，项目快照及宿主出口不变。[HA WebSocket 官方说明](https://contributors.home-assistant.io/core/internals/websocket-api/)。

## 成本和假设

以下为预算，**不是已完成工时或承诺**。按一名熟悉 Python、HTTP/MQTT 与本项目的工程师，每人日 6–8 小时估计，覆盖单台目标机型及基础错误处理；不含未知认证阻断、全机型、相机、打印控制及公网部署。

| 比较 | A 自研 | B 封装 pybambu | C HA 桥接 |
|---|---|---|---|
| 提供器初步可验证实现 | 4–8 人日 | 3–6 人日 | 已有 HA 时 1–3 人日 |
| 额外基础设施 | 采集进程 | Python 进程及依赖 | 从零部署 HA 另约 1–3 人日 |
| 维护重点 | 认证、字段、重连 | 上游升级和封装兼容 | HA/集成与实体映射 |
| Bambu token 所在 | 仅 PC 私有存储 | 仅 PC 私有存储 | HA |
| 本地 MQTT | 不需要 | 显式关闭 | 显式跳过 |
| 独立分发 | 适合 | 需依赖及许可管理 | 要求用户已有或部署 HA |

三者共同还需宿主能力核实与 USB 变量投影，暂留 **2–5 人日**，不计入上表。若宿主/固件缺原语，须重新估算，不承诺只写适配器即可上屏。上述 spike 预算包含在提供器估算中，不重复相加。

## 显示出口是共同待验证项

已有 `widget/data` 列表协议**不等于**组件自定义surface的13个变量更新协议。本机PetUI 0.1.232校验器核实：composition总变量≤8，service bridge标量绑定≤8；PC fetch每来源映射≤8，拆8＋5可通过声明校验，但其不支持Authorization/本机HTTP、刷新≥60秒，不能因此接通私有实时采集服务。常规v2的16变量预算也不代表这些宿主路径已扩容。`app/snapshot`有变量投影入口记录，仍需追踪生产实现、协商和设备接收；详见 [实施计划M0](IMPLEMENTATION-PLAN.md)。

HTTP 快照、SSE 或 WebSocket 只是未来独立服务的候选出口，本工程尚未实现服务或分配路由。HTTP JSON 不会自动进入屏幕。改写 `init` 只能改变初始显示，不能当作实时刷新；每条遥测重新打包也不是实时投影方案。

## 方案选择后的 spike 与验收

以下保留各路线的历史spike估算，均未执行。当前按A实施，先做M0宿主核实并并行推进M1离线核心；真实认证、云联调与设备阶段见 [实施计划](IMPLEMENTATION-PLAN.md)。账号区域、机型/固件和本地私有认证输入在需要时再确认。

| 路线 | 建议 spike 预算 | 关键证据 |
|---|---|---|
| A | 1–2 人日 | 交互登录、设备选择、云首条状态、脱敏字段存在性记录 |
| B | 1–2 人日 | 固定模块独立运行、依赖/副作用清单、回调与资源清理 |
| C | 已有 HA 时 0.5–1 人日 | 云模式、未连本地 MQTT、实体/单位与变化订阅 |

验收要求：

1. 账号操作只在用户本地入口完成，仓库、包及日志没有凭据或原始账户响应。
2. 明确选择设备，确认区域及固件，证明使用云 broker 且未访问打印机本地 MQTT。
3. 初始化和增量合并正确，缺测、不支持、过期与有效 0 可区别。
4. 断网、重连、设备离线与凭据失效分别表达；不无限登录或自动重复发验证码。
5. 连续观察至少 30 分钟，覆盖一次自然发生的任务状态变化；不擅自控制打印机制造事件，完整任务及更长稳定性验收另记录。
6. 真实快照通过内部 schema；合成样例仅离线测试，不上屏冒充实时。
7. 宿主投影单独实测，验证真实变量、翻页及断线行为。云 spike 通过不代表 USB/实机通过。

历史建议是已有HA时评估C、独立低依赖时评估A、多机型复用时评估B。**用户现已选择A，不再重新选型。** 后续变更方案须由新的需求或用户决定驱动，不能因尚未实现的宿主入口自动改为B/C。
