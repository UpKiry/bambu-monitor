## 宿主核实：不能漏掉的事实

本机核实过PetUI `0.1.232` 文档与Python校验器，并做了不联网的声明验证：

| 路径 | 已知限制 |
|---|---|
| composition | 当前总变量≤8；8项声明通过，13项拒绝 |
| service bridge | 当前标量bindings≤8，须精确覆盖vars |
| PC fetch | 单来源≤8；两个来源8＋5的声明可通过，不等于能运行或上屏 |
| PC fetch网络 | 不接受Authorization、本机HTTP/私网；轮询≥60秒，不能承接本地私有实时服务 |
| 当前组件配额 | p4-quota-v2一般允许16vars，但不能据此推断宿主/传输也支持16 |
| app/snapshot | 有宿主入口参考，生产源码、完整传输与目标设备仍待核验 |

宿主Rust源码和目标设备握手尚未取得。安装应用中存在的候选能力、离线默认capabilities和组件包校验成功都不是目标设备支持证据。

M0先确定保留13项及质量状态所需的完整预算。不得悄悄删减指标、申请新能力、修改已安装技能、绕过导入校验或写原始串口。若需要外部Pet Manager/固件源码，先查明并向用户说明具体路径/范围；缺少这些输入时继续M1离线工作。

## 实施起点

1. 检查工作区改动、分支和实际依赖；保留用户内容，不重置、不清理。
2. 加载当前PetUI技能，按本机目录定位真实契约，不使用作者电脑的硬编码home路径。
3. 建立可执行任务清单。优先M0证据报告与M1消息解析/合并/质量/回放核心，分别记录进度。
4. 为M1建立真实边界的测试向量：首次未知、有效0、增量缺席、稳定字段、代次切换、AMS乱序/移除、断网和凭据失效。不要把静态快照打印器当作采集器。
5. M2/M3才需要本地真实认证和云联调；未获得凭据也可通过可替换HTTP/MQTT接口覆盖离线行为。
6. M4以后按M0确定的授权范围接宿主，M5先确认UI预览，M6分别报告PC/云/USB/实机结果。

没有额外授权时，实施范围是本仓库。用户并未在交接中授权修改安装应用、系统profile、外部固件或自动发布组件。

## 固定边界

- 使用Bambu云MQTT，不访问打印机本地MQTT，不自动回退LAN。
- 自研必要协议实现，不引入HA、整个pybambu或相机/FTP/模型下载作为隐藏依赖。
- 不承诺可靠token自动刷新；认证失败进入auth_required并停止无效重试。
- 增量字段未出现保留旧时间；在可靠的同一代次下，稳定字段不因60秒没变化就误判stale；broker连接也不证明打印机在线。
- 单个当前设备、单个选定喷嘴、单个选定AMS的四槽显示；不默认取第一项、不伪造不支持指标。
- 所有正式数据必须有来源和质量；离线fixture/合成数据要明确标识，不能当成实时交付。
- 不预设尚未实现的HTTP/IPC路由，不将新增source名字当作宿主能力。
- 提交/推送、打包、导入、同步和实机验收分开记录。新会话按实际用户指令决定Git操作，不把既有公开仓库当成自动发布授权。
