# 方案 A：需求规格

## 状态、目标与范围

**已选择方案 A：自研 Bambu Cloud 只读适配器。本文是待实施需求，不代表功能已经实现。** 当前会话只整理文档，后续实现由新会话按 [实施计划](IMPLEMENTATION-PLAN.md)推进，验收以 [验收规格](ACCEPTANCE.md)为准。

目标是在一台电脑上完成“交互认证 → 明确选择一台绑定打印机 → 云 MQTT 遥测 → 规范化快照 → Pet Manager 宿主 → 现有三页界面”，准确表达连接、缺测和数据质量。Python 是参考采集器的默认工程方向；原生 Rust、独立服务或桌面附属进程的最终宿主集成形式，由 M0 的实际接口证据决定。

MVP 限定：一个账号、一个明确选择的区域、一台当前选定打印机；设备发现可以返回多台。设计支持 `cn` 和 `global` 两种区域映射，首轮真实验证只要求一个实际账号区域及一个目标机型/固件组合；未实测的区域、登录分支和平台必须列为待验证。界面保持单喷嘴、一个选定 AMS 的四槽投影，不承诺所有机型具备全部 13 项读数。多账号并发、LAN MQTT、HA、pybambu 封装、相机、FTP、打印文件、任务控制、公开数据中转及 NAS 分发不在本次 MVP 范围。

本项目的 [快照 Schema](../schemas/printer-snapshot.schema.json)是内部数据结构，不是 USB 协议。[配置样例](../examples/provider.example.toml)尚无加载器。接口研究中的域名与认证分支见 [云协议记录](CLOUD-PROTOCOL.md)，它们不是稳定官方开放 API。

## 阶段和门禁

| 阶段 | 要交付的证据 | 对缺少设备或凭据的处理 |
| --- | --- | --- |
| M0 宿主可行性 | 宿主源码/接口、真实能力、13 项变量及质量状态的投影路径与扩展范围 | 可先做只读审计和离线校验；实机能力记为待验证，不得宣称完整通路已通过 |
| M1 离线核心 | fake HTTP/MQTT、协议解析、认证状态机、回放、质量规则、生命周期测试 | 无需真实账号和设备，应继续实施 |
| M2 认证和设备发现 | 本地认证入口、密钥库、区域和显式设备选择 | 缺凭据时离线覆盖认证分支，真实账号结果记为待验证 |
| M3 云 MQTT 和可靠性 | 首帧、增量、代次隔离、liveness 与恢复记录 | 缺凭据时以 fake/回放推进，真实云待验证 |
| M4 宿主集成 | 已确认接口的消费、变量快照及 USB 调度 | 需要 M0 决策和已授权的外部代码范围；可先消费明确测试快照 |
| M5 数据状态 UI | 质量/身份状态预览、指标映射和生成基线 | 预览确认后实施，不静默减少 13 项指标 |
| M6 端到端验收 | 真实账号、自然任务变化、USB 与设备显示 | 缺少硬件/账号时明确保留未验收项，不影响 M1 离线交付 |

M0 优先开始。缺少外部宿主源码时，只记录所见契约、待查接口和需要取得的源码/设备证据；不得修改已安装应用、技能缓存或固件来制造支持。M0 未闭合前可以开发来源无关的离线采集核心，不选择不可逆的宿主分发方式，不承诺完整上屏工期。

本机 0.1.232 工具链的已核实边界应作为 M0 输入：composition 总变量最多 8，service bridge 绑定最多 8；PC fetch 每来源最多 8 个映射，拆为 8+5 可以通过声明校验，但不提供认证头、localhost/私网读取，最短轮询间隔 60 秒。一般 `p4-quota-v2` 的 16 变量预算不等于这些宿主适配器已扩容。当前 13 项 UI 不得为了绕过门禁而静默减少；布局或指标范围的变化需单独确认。

| FR-07 | **增量合并与作用域。** 按字段、AMS ID、槽 ID 合并，区分完整基线、增量缺席、明确删除和空槽；维护会话 generation、任务 epoch、槽耗材身份 epoch。 | 未出现字段不被清零；任务或耗材身份变化不沿用旧任务/旧耗材的有效值。重连旧值仅作为旧缓存，不能靠任意首个 delta 重建完整基线。 |
| FR-08 | **基于证据的数据质量。** 按下文的字段类别、协议 profile 和失效规则计算 `valid/stale/unknown/unsupported`。观测时间与持续有效性依据分离。 | 心跳持续但字段值不变时，不机械地在 60 秒后将总层数、AMS 或已确认 delta-retained 指标全部判 stale；也不伪造字段 `updated_at`。 |

| FR-11 | **生命周期与恢复。** 服务有明确启动/停止，退出、停用、切设备、断网、重认证时撤销旧 generation；关闭连接、定时器、线程和待发布队列。 | 旧回调不能发布到新设备/新宿主实例；恢复指数退避并带 jitter；认证拒绝停止无效重试。采集器不抢占 USB，不删除用户已有媒体或其他组件缓存。 |
| FR-12 | **离线回放与诊断。** 提供与真实传输共用解析、状态和投影逻辑的可控假传输/脱敏回放；输出诊断仅含必要事件和类别。 | 无账号、无设备可完成 M1；fixture 明确为合成/脱敏，不能上屏冒充实时。诊断能追踪 generation、profile、字段质量依据及恢复原因，无凭据和全量账户响应。 |

## FR-08：可执行的新鲜度策略

### 三类时间和身份

`metric.updated_at` 保持现有 Schema 语义：**最近一次实际观察到该字段有效值的时间**。字段明确出现在新报文中，即使数值相同也是一次新观察；字段未出现、收到 MQTT ping、生成快照或重发 UI 均不能改它。若上游没有可信测量时间，使用接收观察时间并在 PC metadata 标明来源，不能称为设备测量时间。`generated_at` 仅表示快照生成时间。

提供器在 PC 侧另维护以下 metadata，不将未声明字段塞进当前严格 Schema：

| metadata | 作用 |
| --- | --- |
| `identity_scope` | 账号引用、区域、设备 ID；不包含秘密 |
| `session_generation` | 每次建立/恢复目标订阅的代次，防止旧回调和旧基线重用 |
| `baseline_generation` / `baseline_complete` | 明确本代基线是否完整及包含哪些字段；首个任意 delta 不等于完整基线 |
| `last_target_evidence_monotonic` | 最近有效目标遥测/经 profile 确认的设备活跃事件；与 broker ping 分离，用单调时钟判 liveness |
| `field_last_observed` / `field_basis` | 实际观察时间及 `explicit / delta-retained / task-scoped / tray-scoped` 依据 |
| `job_epoch` / `tray_epoch` | 任务、槽耗材或拓扑身份；身份改变使旧字段失效 |
| `protocol_profile` | 已验证的字段位置、单位、完整/增量判据、遗漏语义和允许作为目标证据的消息类型 |

`connection.last_message_at` 是最近有效目标遥测的墙钟时间，不因纯 broker ping 更新。身份和 freshness 判定使用 generation 与单调时钟，避免墙钟跳变造成假新鲜或错误超时。

### 字段类别与默认规则

MVP 必须对首个明确支持的 profile 写出字段分类和基线判据。下表是实施要求；未来 profile 可以细化，但不能省略依据。当前代的明确有效字段可以单独成为 valid；“未再次出现却继续有效”的保留推断才要求相应完整基线和遗漏语义证据。单字段恢复不得被提升为整代基线完整。

| 类别 | 示例 | 维持 valid 的条件 | 失效与恢复 |
| --- | --- | --- | --- |
| 已确认的 delta-retained 遥测 | 喷嘴/热床/腔温、风扇；仅限 profile 已确认“遗漏表示未变化” | 字段已在当前完整基线或有效显式消息出现，基线属于当前 generation，目标 liveness 有效，且没有对应设备/能力失效事件 | liveness 失效或 generation 改变时，已有值保留为 stale；重新取得本代完整基线或足够明确的字段证据后恢复。不得以字段年龄单独触发统一 60 秒 stale。 |
| 任务作用域 | 总层数、当前层、进度、剩余时间 | 当前任务身份已确认且未变化，当前 generation 的基线有效，目标 liveness 有效，遗漏语义已确认 | 任务切换/新任务准备/身份不明时，旧任务值不能作为当前有效值；明确新任务但未取得值时为 unknown。完成态处理按 profile 明确，不自行倒计时或推导完成。 |
| 槽/耗材作用域 | AMS 槽余量 | 已观察的 AMS/槽和耗材身份仍有效，当前代基线有效，目标 liveness 有效 | 换料、槽移除、明确空槽或拓扑失效时撤销旧余量；新耗材未上报余量为 unknown。稳定槽位超过 60 秒无余量消息仍可保持 valid，原 `updated_at` 不变。 |
| 未确认 profile 或无法确认遗漏语义 | 新固件未知嵌套字段、无法识别的任务/槽身份 | 不启用 delta-retained 推断；首版仅对列入支持 profile 的字段承诺持续有效性 | 不能据“还有其他字段消息”无限续用旧值。未观察为 unknown；存在旧值但有效性无依据时为 stale，并诊断 unsupported protocol/profile。新增 profile 需离线证据和真实云验证。 |
| 能力确认不支持 | A1 系列无辅助风扇等已确认项目 | 不属于 valid | `unsupported`，值和时间为 null；未知能力先用 unknown。 |

**活跃证据阈值的设计初值是 60 秒，不是所有字段的 TTL，也不是云 SLA。** 只有目标消息中经过 profile 确认的有效遥测或设备活跃事件可以续目标 liveness。完整 baseline 后，持续只报告变化字段的有效 delta 维持本代会话；broker ping、其他设备报文、无效 JSON、普通 HTTP 查询都不能续期。阈值须随目标 profile 实测和可配置，不以周期性 `pushall` 强行制造心跳。

本代 liveness 超时后，对已有数值转 stale，未获得数值继续 unknown，能力不支持继续 unsupported；连接状态可用 `offline`，PC 原因必须标为“目标遥测无证据”，不能宣称设备已断电。明确离线事件可以立即失效。重连递增 generation，旧值保留 stale，直到本代基线/字段和作用域证据重新建立；不得用另一台机器或新任务的心跳恢复它。

单个字段出现非法值属于局部失效，不清空全部其他字段；有历史值则 stale、从未有值则 unknown，诊断记录字段原因。能否继续使用省略字段必须由该字段类别与 profile 决定。Schema 自身不表达这些持续性依据，消费者不能仅凭 `updated_at` 距现在的时长重新定义质量。

## 非功能需求

| 编号 | 需求与工程目标 | 验收边界 |
| --- | --- | --- |
| NFR-01 | **凭据和最小出口。** 秘密只经本机私有交互入口进入内存或系统密钥库；不出现在聊天、argv、环境变量示例、源码、fixture、日志、快照或组件包。系统密钥库不可用时默认只在本次会话内存保存，明确告知重启后需重登，不自动明文落盘。 | 使用 canary 凭据的 fake 测试检查所有出口；真实云仅由用户本地授权。日志检查覆盖错误分支和异常对象，不能只删正常日志。 |
| NFR-02 | **响应性。** 在受支持目标环境，单条已接收有效报文到规范化快照发布的工程目标为 P95 ≤1 秒；宿主已连接时从可发布快照到可见更新目标为 P95 ≤2 秒；liveness 到期后 ≤5 秒呈现质量/连接变化。 | 使用本机可控时钟和时间点测量，注明负载与平台；这些不包含云送达延迟，不承诺云固定推送频率。离线测试与 HIL 时延分开报告。 |
| NFR-03 | **有界可靠性。** 单设备单订阅；网络、认证、缓存和宿主发布分离，后台工作/队列有明确上限。重连设计初值1秒、上限60秒并带jitter；认证失败不进入无限循环。 | 压力测试证明队列不无限增长、过载有可诊断策略、旧代任务不能重放；退出目标为停止请求后5秒内完成本地资源回收，超时明确报告，不把远端阻塞伪称已停止。 |
| NFR-04 | **可移植与可维护。** 核心支持项目约定的 Python 3.11+，不写死用户路径；依赖、profile、运行目录、非秘密配置有文档。数据模型与传输/UI分离。 | 首个交付平台必须明确；其他系统只在对应运行证据存在时宣称支持。宿主sidecar/原生Rust或NAS分发不因Python单测通过自动获得兼容承诺。 |
| NFR-05 | **分层证据和回归。** 需求、测试、协议profile与未验证项可追踪；现有离线组件、ID、版本和清单打包规则保持回归。 | M0审计、单元/回放、fake集成、真实云与HIL分别报告；缺设备/凭据时可完成离线交付，真实层保留待验证，不能标为整体通过。 |

## 完成判定

文档完成只意味着需求和验收已明确。MVP 完成必须同时有：已闭合的 M0 决策、M1 自动化证据、至少一台明确机型/固件的 M2–M3 真实云证据、M4 宿主集成、M5 状态 UI 和目标设备上的 M6 端到端证据，以及 [验收规格](ACCEPTANCE.md)中全部适用项的结果。单纯取得云首帧、通过 Schema、生成组件包或显示测试数字均不足以替代这些证据。
